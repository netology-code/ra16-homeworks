Состояние компонентов
===
## Выполнив это задание, вы:

- научитесь создавать и управлять состоянием в классовых компонентах с помощью `this.state` и `this.setState()`;
- поймёте, как организовывать взаимодействие между компонентами, передавая функции-обработчики через props (принцип «поднятия состояния»);
- научитесь фильтровать и отображать данные в зависимости от состояния компонента;
- попрактикуетесь в условном рендеринге для переключения между различными вариантами отображения интерфейса;
- увидите на практике, как изменение состояния автоматически приводит к обновлению пользовательского интерфейса;
- (в необязательном задании) познакомитесь с хуком `useState` для работы с состоянием в функциональных компонентах.

Состояние (state) — это сердце любого интерактивного React-приложения. Это задание научит вас использовать состояние для создания интерактивных интерфейсов. Вы увидите, как по клику пользователя фильтруются списки или меняется вид отображения элементов. Умение управлять состоянием — это важный навык, необходимый для разработки приложений на React, где интерфейс динамически обновляется в ответ на ввод пользователя.

## Описание задания

Необходимо выполнить и предоставить на проверку следующие задачи:

1. [Портфолио с фильтрами](filter).
1. [Расположение товаров](layouts).

## Инструкция к выполнению

Все три задачи лучше сдавать в разных репозиториях, то есть через vite реализовать три проекта, чтобы не
было конфликта стилей. Но если вы позаботитесь о том, что конфликта не будет, то можете сдавать и в одном проекте.

Все стили необходимо размещать в файле App.css.

Документация по созданию приложения [React](https://vitejs.dev/guide/).

1. Откройте терминал и пропишите следующую команду: `yarn create vite my-app --template react`,
   либо `yarn create vite my-app --template react-ts`, если
   нужен шаблон с TypeScript. Эта команда создаст настроенный
   шаблонный проект.
2. Откройте созданный проект в своей IDE.
3. Установите зависимости.
4. Готово. Чтобы запустить приложение, введите команду: `yarn dev`(либо `npm run dev`).

## Критерии оценки

**Зачёт:**

* Задача «Портфолио с фильтрами»:   

   * Компонент `Portfolio` управляет состоянием, храня в нём активный фильтр.   

   * При клике на фильтр в `Toolbar` меняется активный фильтр, и список проектов в `ProjectList` перерисовывается в соответствии с выбранной категорией.   

* Задача «Расположение товаров»:

   * Компонент `Store` хранит состояние о выбранном виде отображения.

   * При клике на иконку в `IconSwitch` происходит смена отображения товаров с `CardsView` на `ListView` и обратно (условный рендеринг работает корректно).

* Общие требования к коду:

   * Состояние изменяется корректно через `this.setState()`, без прямой мутации `this.state`.

   * Взаимодействие между компонентами организовано через props: родительские компоненты передают дочерним данные и функции-обработчики для обновления состояния («поднятие состояния»).

   * Приложение запускается и работает без ошибок в консоли.

Выполнение необязательной задачи с выпадающим списком является плюсом и демонстрирует более глубокое понимание темы.   

**На доработку:**

* Не выполнено одно из обязательных заданий («Портфолио с фильтрами», «Расположение товаров»).

* Ключевая функциональность одной или обеих обязательных задач не работает: фильтрация не происходит или вид отображения не переключается.

* Состояние изменяется напрямую (например, `this.state.selectedFilter = 'new'`), а не через метод `this.setState()`.

* Логика управления состоянием находится в дочерних компонентах, а не в родительском (например, `Toolbar` сам пытается управлять активным фильтром, вместо того чтобы сообщать об этом Portfolio).

* Данные (проекты, товары) фильтруются или преобразуются не в том компоненте, который владеет состоянием. Например, `ProjectList` получает все проекты и сам их фильтрует, вместо того чтобы получать уже отфильтрованные от `Portfolio`.

* В работе присутствуют ошибки, которые мешают приложению запуститься или корректно работать.
